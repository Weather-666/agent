# Experts API

Expert management is platform-scoped. Expert categories are the taxonomy used
by experts; each expert belongs to exactly one category.

Expert groups are authorization groups used by plans. They are separate from
expert categories: categories are for marketplace taxonomy, while groups are for
plan access control.

## Expert Categories

```text

```

All endpoints require:



## Expert Shape

```json
{
  "id": "0123456789abcdef",
  "name": "Amazon Listing Expert",
  "categoryId": "expert_cat_123",
  "categoryName": "Amazon Operations",
  "groupId": "expert_group_basic",
  "groupName": "基础专家组",
  "abilityIntro": "Helps optimize Amazon listings and reviews.",
  "tags": ["listing", "reviews"],
  "marketLabels": ["hot"],
  "status": "draft",
  "skillIds": ["skill_1", "skill_2"],
  "knowledgeBaseIds": ["kb_1", "kb_2"],
  "guideQuestions": [
    "How can I improve my listing?",
    "Why did my review get removed?",
    "How do I optimize keywords?"
  ],
  "summonButtonText": "Ask this expert",
  "createdAt": "2026-06-03T00:00:00+00:00",
  "updatedAt": "2026-06-03T00:00:00+00:00"
}
```

Status values:

- `published` = published
- `draft` = draft
- `unlisted` = unlisted

`marketLabels` is an expert-level display-label array. The currently supported
value is `hot`; an empty array means that the expert has no market labels.
`id` is an immutable 16-character lowercase hexadecimal `expertId` generated by Backend.

## GET /api/v1/experts

Query parameters (all optional, combinable):

| Parameter | Description |
| --- | --- |
| `name` | Case-insensitive partial expert name. |
| `categoryId` | Expert category ID. |
| `status` | `published`, `draft`, or `unlisted`. |

Example:

```text
GET /api/v1/experts?categoryId=expert_cat_123&status=published
```

Response `200`:

## POST /api/v1/experts

Create an expert. Required permission: `expert:write`.

Request:

```json
{
  "name": "Amazon Listing Expert",
  "categoryId": "expert_cat_123",
  "groupId": "expert_group_basic",
  "abilityIntro": "Helps optimize Amazon listings and reviews.",
  "tags": ["listing", "reviews"],
  "marketLabels": ["hot"],
  "skillIds": ["skill_1", "skill_2"],
  "knowledgeBaseIds": ["kb_1", "kb_2"],
  "guideQuestions": [
    "How can I improve my listing?",
    "Why did my review get removed?",
    "How do I optimize keywords?"
  ],
  "summonButtonText": "Ask this expert"
}
```

Backend generates `id` and always creates the Expert as `draft`; the request accepts neither
identity nor status. `tags`, `marketLabels`, `skillIds`,
`knowledgeBaseIds`, and `guideQuestions` default to empty arrays.
`guideQuestions` accepts at most three items. Array fields are de-duplicated,
preserving first-seen order. Unsupported market-label values return `422`.
Runtime targets default to model `gpt-5.5`; enabled targets cannot use an empty model.
An omitted `maxInstances` defaults to `50` for each Runtime. Explicit values from `1`
to `100` are preserved; the system default Expert does not override this default.
`groupId` is optional. When provided, the backend validates the expert group and
adds the new expert to that group as its primary authorization group.

Response `201`: the expert shape.

Errors:

```text
404 EXPERT_CATEGORY_NOT_FOUND
404 EXPERT_GROUP_NOT_FOUND
404 SKILL_NOT_FOUND
404 KB_NOT_FOUND
422 validation error
```

## PATCH /api/v1/experts/{expert_id}

Update an expert. Required permission: `expert:write`.

Request:

```json
{
  "name": "Updated Expert",
  "categoryId": "expert_cat_456",
  "groupId": "expert_group_professional",
  "abilityIntro": "Updated intro.",
  "tags": ["updated"],
  "marketLabels": [],
  "skillIds": ["skill_2"],
  "knowledgeBaseIds": ["kb_3"],
  "guideQuestions": [],
  "summonButtonText": "Start"
}
```

All fields are optional. Omitting `runtimeConfig` preserves the existing Runtime settings.
When `runtimeConfig` is supplied, each target defaults an omitted `maxInstances` to `50`
and preserves an explicit value. Passing `skillIds` or `knowledgeBaseIds` replaces that
relationship set. Passing `guideQuestions` replaces the guide question list.
Omitting `marketLabels` preserves the current labels; passing `[]` clears all
labels, and passing `["hot"]` marks the expert as hot.
Passing `groupId` switches the expert's primary authorization group. Passing
`groupId: null` clears the primary group. Omitting `groupId` leaves the current
group unchanged.

Response `200`: the expert shape.

Published Experts are read-only. Unlist them through the status endpoint before editing.

Errors:

```text
404 EXPERT_NOT_FOUND
404 EXPERT_CATEGORY_NOT_FOUND
404 EXPERT_GROUP_NOT_FOUND
404 SKILL_NOT_FOUND
404 KB_NOT_FOUND
409 EXPERT_PUBLISHED_READ_ONLY
422 validation error
```

## PATCH /api/v1/experts/{expert_id}/status

Publish or unlist an expert. Required permission: `expert:write`.

Request:

```json
{
  "status": "published"
}
```

Response `200`: the expert shape.

`published` runs the complete local Builder, Gateway Service/Route, VirtualKey allowlist and real
ACP Turn validation flow before the status changes. `unlisted` disables both Runtime resources
before the status changes. Same-status requests are idempotent. `draft` is not accepted.

Errors:

```text
404 EXPERT_NOT_FOUND
409 EXPERT_STATUS_TRANSITION_INVALID
502 EXPERT_BUILDER_FAILED
502 EXPERT_GATEWAY_ADMIN_ERROR
502 EXPERT_RUNTIME_SMOKE_FAILED
503 EXPERT_BUILDER_UNCONFIGURED
422 validation error
```

## DELETE /api/v1/experts/{expert_id}

Delete an expert. Required permission: `expert:write`.

Response:

```text
204 No Content
```

Deleting an expert cascades its `expert_skills` and `expert_knowledge_bases` relationships. An
Expert referenced by an active Chat Session cannot be deleted. After all of its Chat Sessions
have been deleted, Expert deletion clears the historical Session/Turn `expertId` foreign key.

Errors:

```text
404 EXPERT_NOT_FOUND
409 EXPERT_IN_USE
```

## Expert Market

Base path:

```text
/api/v1/expert-market
```

All market endpoints require a signed-in caller but no platform permission.
Expert list and detail additionally require a valid active tenant context.

### GET /categories

Returns category filter information for categories that contain selectable
published experts. The response retains the existing category filter shape
(`id`, `name`, and `description`) and does not include expert-card labels.

### GET /experts

Returns published experts except the reserved system default Expert. The
optional `categoryId` query parameter keeps the existing category filter
behavior. Each expert item includes `marketLabels` and `isAccessible`. The access
value is computed once from the active tenant's current plan: `allExperts` or
explicit membership in the plan's `expertIds`. Labels do not affect the existing
`createdAt desc, id asc` ordering.

### GET /experts/{expert_id}

Returns a selectable published expert including `marketLabels` and
`isAccessible`. Draft, unlisted, and reserved system-default experts return
`404 EXPERT_NOT_FOUND`.

`isAccessible=false` is informational for market display. Creating an Expert
Session or starting a Turn for an existing Expert Session enforces the same
decision and returns `403 EXPERT_NOT_INCLUDED_IN_PLAN` when denied.
