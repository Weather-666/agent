# Documents API

Base path:

```text
/api/v1/knowledge-bases/{knowledge_base_id}/docs
```

Documents are **platform-authored resources** nested under a knowledge base. Like knowledge
bases, they have no tenant relationship. All endpoints require a platform role and the
relevant `doc:*` permission, plus resource-level authorization on the parent knowledge base
(see [knowledge-bases.md](./knowledge-bases.md)).

Uploads use the configured object storage backend. With `minio`, the API mints a short-lived
presigned URL and the client PUTs straight to MinIO/S3. With `local`, the API returns a
short-lived backend-controlled `/api/v1/storage/objects/{token}` URL; the client still uses PUT,
but FastAPI receives the bytes and writes them under the configured local object directory. There
are no top-level `/documents/*` or `/uploads/*` routes.

The signed PUT target is generated by Backend, never the client:

```text
knowledge-bases/{knowledge_base_id}/uploads/{upload_session_id}/{safe_file_name}
```

It is temporary because the presigned PUT remains reusable until expiry. On completion Backend
copies verified bytes to the durable immutable key:

```text
knowledge-bases/{knowledge_base_id}/documents/{document_id}/versions/{sha256}/{safe_file_name}
```

Allowed file types (whitelist): `pdf`, `docx`, `pptx`, `xlsx`, `md`, `txt`, `html`, `csv`, `json`.

## POST /upload-url

Request a presigned upload URL. Required permission: `doc:create`.

Request:

```json
{
  "fileName": "guide.pdf",
  "mimeType": "application/pdf",
  "fileSizeBytes": 102400,
  "contentHash": "sha256_optional"
}
```

The file type is resolved from the extension against the whitelist; unsupported types are
rejected (`400 DOC_UNSUPPORTED_TYPE`).

Response:

```json
{
  "uploadSessionId": "upl_123",
  "documentId": "doc_123",
  "method": "PUT",
  "uploadUrl": "https://minio.example.com/expert-docs/...",
  "headers": { "Content-Type": "application/pdf" },
  "objectKey": "knowledge-bases/kb_123/uploads/upl_123/guide.pdf",
  "expiresAt": "2026-06-03T10:10:00Z"
}
```

The client then `PUT`s the file body to `uploadUrl`. In `minio` mode this goes to MinIO/S3; in
`local` mode it goes to the backend's signed storage route. Local upload URLs enforce the
declared `fileSizeBytes` and `Content-Type` from the upload session while streaming the body to
disk, so oversized uploads are rejected before completion. Requests whose declared
`fileSizeBytes` exceeds `EXPERT_OBJECT_STORAGE_MAX_UPLOAD_BYTES` are rejected before an
upload URL is signed.

## POST /upload-urls

Request presigned upload URLs for multiple documents. Required permission: `doc:create`.

Request:

```json
{
  "files": [
    {
      "fileName": "guide.pdf",
      "mimeType": "application/pdf",
      "fileSizeBytes": 102400
    },
    {
      "fileName": "notes.txt",
      "mimeType": "text/plain",
      "fileSizeBytes": 4096
    }
  ]
}
```

This batch is **non-atomic**: each file is processed independently and reported in `items`
with `status` `created` or `failed`. A failed file carries an `error` (`code` / `message` /
`details`) and does not abort the others, so the client retries only the failures.

Response `200 OK`:

```json
{
  "items": [
    {
      "fileName": "guide.pdf",
      "status": "created",
      "upload": {
        "uploadSessionId": "upl_123",
        "documentId": "doc_123",
        "method": "PUT",
        "uploadUrl": "https://minio.example.com/expert-docs/...",
        "headers": { "Content-Type": "application/pdf" },
        "objectKey": "knowledge-bases/kb_123/uploads/upl_123/guide.pdf",
        "expiresAt": "2026-06-03T10:10:00Z"
      },
      "error": null
    }
  ]
}
```

The client then `PUT`s each file body to its corresponding `upload.uploadUrl`.

## POST /complete-upload

Confirm the upload and create the document record. Required permission: `doc:create`.

Request:

```json
{
  "uploadSessionId": "upl_123",
  "etag": "minio-etag",
  "fileSizeBytes": 102400
}
```

The API HEADs the object and **enforces the declared size**: the stored object size must equal
`upload_sessions.file_size_bytes` recorded at upload-url time. A presigned PUT does not bound
the written size, so the HEAD size is authoritative — the client-provided `fileSizeBytes` is
never trusted. On mismatch the session is failed, the object is removed, no document is created,
and `400 UPLOAD_SIZE_MISMATCH` is returned.

Backend then reads the exact stored bytes, computes SHA-256 server-side and copies them to the
immutable version key. That computed digest is the persisted `contentHash`; client `contentHash`,
completion `etag` and completion `fileSizeBytes` are not trusted as integrity proof. Document
creation creates one deduplicated automatic sync job in the same transaction and removes the
temporary PUT object after commit.

Response `201 Created`:

```json
{
  "id": "doc_123",
  "knowledgeBaseId": "kb_123",
  "fileName": "guide.pdf",
  "fileType": "pdf",
  "mimeType": "application/pdf",
  "fileSizeBytes": 102400,
  "storageKey": "knowledge-bases/kb_123/documents/doc_123/versions/abc.../guide.pdf",
  "contentHash": "abc...",
  "sourceSha": "abc...",
  "indexedSha": null,
  "indexDocumentId": null,
  "parseStatus": "pending",
  "indexStatus": "pending",
  "metadata": {},
  "createdAt": "2026-06-03T10:00:00Z",
  "updatedAt": "2026-06-03T10:00:00Z"
}
```

The response is intentionally not retrievable yet. The background worker verifies the immutable
source again, converts it with Docling/OCR, stores content-addressed Markdown, inserts it into this
KB's isolated LightRAG endpoint and polls to a terminal state. Retrieval starts only when
`indexStatus=ready`, `indexDocumentId` is non-null and `indexedSha == sourceSha`.

## POST /{document_id}/upload-url and /{document_id}/complete-upload

Replace the immutable original of one logical Document without changing its id. Both endpoints
require `doc:update` and use the same request/PUT handshake as create. The returned replacement
session can only be completed at the matching `/{document_id}/complete-upload` route; a
`doc:create` completion cannot consume it.

Completion returns `200 OK`, records the new source generation and automatic sync job in one
transaction, and immediately removes the Document from retrieval because the new `sourceSha` no
longer equals `indexedSha`. The worker deletes the exact prior `indexDocumentId` before inserting
the new generation. Original and Markdown generations are retained by `(documentId, sourceSha)` so
historical citations can still resolve the exact bytes until the Document is deleted and GC runs.
No Expert republish is needed.

## POST /complete-uploads

Confirm multiple uploads and create their document records. Required permission:
`doc:create`.

Request:

```json
{
  "items": [
    {
      "uploadSessionId": "upl_123",
      "etag": "minio-etag",
      "fileSizeBytes": 102400
    }
  ]
}
```

Like `/upload-urls`, this batch is **non-atomic**: each item commits on its own and is
reported in `items` with `status` `completed` or `failed`. A `completed` item carries the
created `document`; a `failed` item carries an `error` (`code` / `message` / `details`) and
the caller retries only the failures. The endpoint returns `200 OK` even when some items fail.

Response `200 OK`:

```json
{
  "items": [
    {
      "uploadSessionId": "upl_123",
      "status": "completed",
      "document": {
        "id": "doc_123",
        "knowledgeBaseId": "kb_123",
        "fileName": "guide.pdf",
        "fileType": "pdf",
        "mimeType": "application/pdf",
        "fileSizeBytes": 102400,
        "storageKey": "knowledge-bases/kb_123/documents/doc_123/versions/abc.../guide.pdf",
        "contentHash": "abc...",
        "parseStatus": "pending",
        "indexStatus": "pending",
        "metadata": {},
        "createdAt": "2026-06-03T10:00:00Z",
        "updatedAt": "2026-06-03T10:00:00Z"
      },
      "error": null
    }
  ]
}
```

## GET /

List documents in a knowledge base. Required permission: `doc:read`. Soft-deleted documents are
excluded.

```json
{ "items": [ { "id": "doc_123", "...": "..." } ] }
```

## GET /{document_id}

Get a document. Required permission: `doc:read`.

## PATCH /{document_id}

Update document metadata / file name. Required permission: `doc:update`.

```json
{ "fileName": "renamed.pdf", "metadata": {} }
```

This endpoint changes descriptive metadata only. It does not copy knowledge into an Expert Runtime
or require publication.

## DELETE /{document_id}

Soft-delete a document. Required permission: `doc:delete`. Response: `204 No Content`.

The row is marked `deleted_at` before commit and is therefore excluded from every new retrieval
immediately. A durable delete job removes only its exact external LightRAG document. GC then
reclaims every immutable source/Markdown generation and the row.

## GET /{document_id}/download-url

Mint a short-lived GET URL for the document object. Required permission: `doc:read`. In `minio`
mode this is a MinIO/S3 presigned URL; in `local` mode it is a backend-controlled
`/api/v1/storage/objects/{token}` URL, never a filesystem path.

MinIO mode signs only against the explicitly configured browser-facing public endpoint and fails
with `OBJECT_STORE_UNAVAILABLE` when that endpoint is missing, internal or invalid. It never falls
back to the Backend-to-MinIO endpoint. Local mode always returns a same-origin relative path. The
signed response includes an attachment `Content-Disposition` with the document display filename.

```json
{
  "method": "GET",
  "downloadUrl": "https://minio.example.com/expert-docs/...",
  "expiresAt": "2026-06-03T10:10:00Z"
}
```
